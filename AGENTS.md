# JRH AI Coding Rules

## Required reading
For any UI, UX, copy, responsive, accessibility, or visual-code task:
1. Read `DESIGN.md` for JRH design direction.
2. Read `antislop.md` for quality and anti-slop constraints.
3. Treat both as project constraints; do not replace the established JRH identity with generic AI defaults.

## Working mode
Apply the antislop filter DURING the work. Do not wait until the end to catch generic output.

## Preservation
Do not invent or silently alter JRH content, personal data, project URLs, images, audio, or other existing assets unless the user explicitly asks for a content change.

## Before completion
Run the project's build/checks where available and perform a final Delivery Gate against `antislop.md`. Do not claim completion when the build is broken or deployment-critical functionality has not been verified.

## UI principle
JRH is an editorial personal portfolio, not a SaaS template. Prefer hierarchy, typography, whitespace, real content, and purposeful interaction over decorative effects.
